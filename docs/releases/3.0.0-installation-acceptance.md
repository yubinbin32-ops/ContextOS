## 由真实安装测试修复的问题

1. 显式选择宿主时，新用户目录不再因“未检测到安装”而被静默跳过。
2. canonical server 尊重 `CONTEXTOS_HOME`，同步 parser WASM 与 grammars，独立 AST 不再依赖源码目录。
3. Codex 配置尊重 `CODEX_HOME`；不支持插件的 CLI 路线同时安装两个本地技能。
4. 干净个人 marketplace 不再生成非法的 `[{}, personal]`；现代 Codex 先注册 marketplace source，并初始化配置 home，再安装插件。
5. Codex bridge 的 `exec resume` 去除官方子命令不支持的 `-C`，workspace 通过子进程 cwd 绑定。
6. Codex bridge 输出本次调用 usage，因此指南及 adapter 使用 `aggregation: invocation`；不会把每次调用统计误当会话累计量差分。
7. Micro doctor 使用实际支持的 `role: api`，不是无效的 `role: micro`。

聚焦回归：bootstrap 测试 13/13；Codex bridge 测试 3/3。桥接回归实际执行一个模拟 CLI，验证 resume 参数、cwd、最终文本、线程 ID 和本次调用 usage，而非只检查字符串。

最新 Node 全套验证为 **786/786 通过**，回执 `receipt-1791140395492-27a8f0`；最终 plugin 验证通过，回执 `receipt-1791140494569-17c441`。Swift 全套 **28/28 通过**（`app-full-swift-v3-verified`），Windows App TypeScript 构建通过（`app-win-parallel-cli-editor-build`）；桌面打包通过，回执 `receipt-1791141023150-5799d7`。构建通过不等于跨平台 GUI 或安装验收；App 项目名焦点框的最终截图检查仍在继续。这些是本次发布准备检查，不加入历史 benchmark 用量。
