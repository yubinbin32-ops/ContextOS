# ContextOS 2.7.1：上下文节省测评 / Context reduction benchmark

测量日期：2026-09-30（Asia/Shanghai）。五次独立临时工作区运行，`o200k_base` / js-tiktoken 1.0.21，中位数。环境：Node v22.22.1、macOS arm64。

**结论：大文件、重复读取和高噪声日志有明确的返回上下文收益；首次精确读取与极小任务存在额外开销。尚未测量完整开发任务的模型账单。**

## 测量范围与复现

基准通过真实 stdio MCP 客户端调用发布 bundle。源码来自本仓库的 `pipelines.mjs` 与 `intent-router.mjs`；在临时项目中按相同符号读取。成功、失败日志是明确标注的 1,000 行合成构建日志，不使用外部模型或 API key。

```bash
npm ci
npm run benchmark:context -- --runs 5 --output .contextos/benchmarks/my-run.json
```

脚本：[benchmark-context.mjs](../scripts/benchmark-context.mjs)。本次全部样本：[2026-09-30.json](benchmarks/2026-09-30.json)。记录包含 bundle/source SHA-256、基准运行前的 Git commit、工作树修改标记、分词器版本、每次响应 hash 和耗时。

## 对照结果

| 场景 | 原生输出 token | OS 输出 token | 输出减少比例 | OS 请求参数 token |
| --- | ---: | ---: | ---: | ---: |
| 仓库大文件：整读对比符号切片 | 43,031 | 280 | 99.35% | 30 |
| 同一大文件：精确原生切片对照 | 165 | 280 | -69.70% | 30 |
| 仓库较小文件：整读对比符号切片 | 1,459 | 336 | 76.97% | 27 |
| 同一较小文件：精确原生切片对照 | 220 | 336 | -52.73% | 27 |
| 重复符号读取 | 165 | 36 | 78.18% | 30 |
| 极小文件 | 6 | 66 | -1000.00% | 23 |
| 合成成功日志，1,000 行 | 14,003 | 83 | 99.41% | 24 |
| 合成失败日志，1,000 行 | 14,016 | 150 | 98.93% | 29 |

计算：`(1 - OS 输出 token / 原生输出 token) × 100%`。负数表示 ContextOS 返回更多 token。请求参数单列报告，**没有从原生方案中扣除相应请求成本**；宿主工具定义、会话历史、模型生成和推理也不在输出指标中。重复读取的对照是再次返回同一精确切片；能够自行避免重复读取的智能体，不会自动产生这项节省。

两个精确原生切片对照均多出约 115–116 token；它们让“整文件读取”的收益有可比较的边界。大文件样本含约 4,100 行，因此 99.35% 不应外推到典型小文件或所有任务。较小文件的实测减少比例为 76.97%。

## 固定上下文成本

| 加载内容 | token |
| --- | ---: |
| 单工具定义 | 1,056 |
| 七工具兼容定义 | 2,922 |
| 技能正文 | 1,350 |
| 服务端 instructions | 98 |
| 紧凑工具 + 技能 + instructions | 2,504 |

工具定义压缩约 63.9%。固定成本并非每次调用都重新追加，但宿主可能在每轮重新提交历史上下文；实际计费取决于缓存、宿主加载策略和提供商。此表是增量上下文规模，没有比较宿主自带工具定义的成本。

只看响应差额并假设这些内容加载一次，较小文件每次整读改切片节省 1,123 token，约三次不同读取才能覆盖 2,504 token 的固定成本。这只是输出层的粗略盈亏判断，不能当作模型账单估计。

## 功能质量与修复

每轮通过 12 个场景或质量检查，覆盖：目标符号存在、重复读取去重、磁盘修改后刷新、精确批量区间、多区间行号、成功/失败状态、保留错误原因，以及失败命令阻止后续步骤。

| 已复现的问题 | 修复与验证 |
| --- | --- |
| 多个 inspect 被强制改成 shallow，指定 ranges/symbol 仍只返回大纲 | 明确目标直接保留；两个大文件的并行区间回归通过 |
| 非连续区间被连续编号，第二段显示错误源码行号 | 遇到每段范围标记重置行号；2–3 行与 90–91 行回归通过 |
| 安装复制新内容后，Codex 注册版本仍为旧版；--check 误报通过 | 同步本地来源后刷新注册；同时核验版本、bundle、技能、manifest、MCP 配置及权威服务端 |
| --check 在未安装状态可能触发安装；历史缓存被批量改写 | 检查走只读分支；同步仅针对当前注册版本和来源 |
| 插件缓存缺少解析器资源，Python 退回较弱解析，嵌套方法 hash 显示 undefined、调用信息缺失 | 构建、安装和核验包括 WASM 与语法文件；脱离仓库的 Python 分发验收检查方法哈希和调用信息 |

新读取回归用例在原始实现中 **0/2 通过**，修复后 **2/2 通过**。安装回归使用隔离目录与可控 CLI 桩，验证注册升级、只读拒绝、旧字节拒绝和历史缓存保留；本机另完成真实插件安装与内容一致性检查。

## 交付验证

398 项自动化测试全部通过；插件冒烟、分发布局、真实接入与全新 Codex 市场安装通过。插件缓存、权威服务端与本次测量的 bundle SHA-256 一致；独立分发的 Python 检查保留方法哈希和调用信息。

## 仍可优化的空间

1. **减少首次读取的响应包装**：精确原生对照揭示了约 115–116 token 的位置、标题与回执开销。可研究紧凑输出模式，同时保留真实行号、hash 与失败状态。
2. **进一步缩小技能与工具定义**：当前固定加载约 2,504 token。按任务加载高级能力，避免给简单修改增加完整流程成本；应同时验证指令遵循和失败恢复质量。
3. **以实际模型用量验证总收益**：对相同仓库、同一任务、同一模型做多次智能体 A/B 测试，记录输入、输出、推理、缓存命中、总轮数、费用与最终测试结果。本次数据不足以支持“总 token 节省 50%–90%”。
4. **扩大样本**：加入其他仓库、语言和宿主，以及低噪声、小文件、多文件重构、真实失败日志。当前性能数据仅覆盖两个本仓库文件与明确的合成日志。
