# 意图级开发闭环

1. **入口只有四个**：`explore`（理解/定位/续接）、`change`（改写或新建）、`verify`（跑命令取证）、`ship`（收尾归档）。需要精细控制时才用 `ops`。
2. **照返回值走**：每次响应开头的 `## Next` 是 OS 依据真实状态算出的下一步，默认照它调用，省掉自己编排流程的成本。
3. **不手工记账**：工作集来自 git 与编辑行为（无论你用什么工具改的），回执由 `verify` 自动挂载，模块归属由 AST 派生。不要维护 workingSet、覆盖率台账或任务状态。
4. **不伪造证据**：验证失败就再改一次再 `verify`，不要用 `ops` 去改状态让它"看起来通过"。`strict` 项目下无绿色回执不允许 `ship`。
5. **原生工具是允许的逃生通道**：批量改写、整文件新建、非代码资产或 OS 不可用时可以用原生工具；但要自己承担读入的上下文与缺失的 Receipt，之后随时可以回到循环。
